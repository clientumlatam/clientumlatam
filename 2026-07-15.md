## Hallazgos técnicos clave

### Arquitectura de entrypoints duales

- `server.ts` — para dev/Cloud Run: llama a `app.listen()` + embebe Vite middleware
- `api/index.ts` — para Vercel serverless: NO llama a `app.listen()` porque `VERCEL=1` está seteada

### tsconfig duales (crítico para Vercel)

- El `tsconfig.json` raíz usa `moduleResolution: "bundler"` (requerido por Vite)
- `api/tsconfig.json` sobreescribe con `moduleResolution: "node16"` (requerido por el compilador de Vercel)
- Sin esta separación, Vercel falla en build

### Resolución de base de datos

El servidor intenta en orden:
1. `NEON_API_KEY` + `NEON_PROJECT_ID` → llama a la API de Neon para obtener la pooled URL dinámicamente
2. `DATABASE_URL` como fallback

### Problemas encontrados en `.env.example` anterior

Tenía 8 variables. Le faltaban:

| Variable faltante | Impacto |
|---|---|
| `DATABASE_URL` | Fallback cuando no hay NEON_* |
| `NEON_API_KEY` | Forma preferida de conectar a DB |
| `NEON_PROJECT_ID` | Requerido junto a NEON_API_KEY |
| `CRM_INTERNAL_TOKEN` | Sin esto, webhook WordPress → CRM responde 503 |
| `GOOGLE_MAPS_API_KEY` | Alias legacy que el servidor acepta |
| `PORT` | Necesario para desarrollo local |
| `NODE_ENV` | Runtime; afecta comportamiento de Express |
| `DISABLE_HMR` | Inyectada por Replit; debe estar documentada |
