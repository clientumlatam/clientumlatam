🎯 Principios Clave para Implementación en Replit


Todo debe funcionar en Replit:

Usar librerías compatibles (ej: playwright para scraping, prisma para DB).
Evitar dependencias de sistema operativo (usar contenedores si es necesario).


Despliegue automático en Vercel:

Usar Next.js para frontend + backend (API Routes).
Configurar vercel.json para cron jobs.


Base de datos en Neon:

Usar Prisma ORM para abstraer consultas.
Conectar Neon directamente desde Vercel (variable de entorno DATABASE_URL).


APIs externas:

Todas las APIs deben tener claves configurables en variables de entorno (ej: GOOGLE_PLACES_API_KEY).
Manejar errores y reintentos automáticos.


Agentes reemplazables:

Cada agente debe ser un módulo independiente con interfaz clara (ej: run(task: Task) -> Result).
El Orquestador debe poder cambiar de agente sin modificar el resto del sistema.


Memoria persistente:

Usar Neon para guardar:

Contexto de conversaciones.
Estado de tareas.
Aprendizajes (ej: "El asunto 'X' tiene 30% más apertura").

💾 5. Modelo de Memoria Compartida
📌 Arquitectura de Memoria
Objetivo: Permitir que los agentes aprendan de cada interacción y compartan contexto sin depender de sesiones efímeras.
🔹 Estructura en Neon PostgreSQL
sql
Copiar

-- Tabla principal de memoria
CREATE TABLE agent_memory (
    id SERIAL PRIMARY KEY,
    agent_name VARCHAR(50) NOT NULL,       -- Ej: "Enriquecedor", "Copywriter"
    conversation_id VARCHAR(100),          -- ID de la conversación/lead
    context JSONB NOT NULL,                -- Contexto acumulado (ej: preferencias del lead)
    decisions JSONB,                       -- Decisiones tomadas por el agente
    learnings JSONB,                       -- Aprendizajes (ej: "El asunto X tiene 30% más apertura")
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Tabla de historial de tareas
CREATE TABLE task_history (
    id SERIAL PRIMARY KEY,
    task_id VARCHAR(100) NOT NULL,
    agent_name VARCHAR(50) NOT NULL,
    status VARCHAR(20) NOT NULL,           -- "pending", "in_progress", "completed", "failed"
    input_data JSONB NOT NULL,
    output_data JSONB,
    retries INT DEFAULT 0,
    error_message TEXT,
    tokens_used INT,
    api_calls JSONB,                        -- Registrar qué APIs se usaron
    start_time TIMESTAMP DEFAULT NOW(),
    end_time TIMESTAMP
);

-- Tabla de métricas por agente
CREATE TABLE agent_metrics (
    id SERIAL PRIMARY KEY,
    agent_name VARCHAR(50) NOT NULL,
    date DATE NOT NULL,
    tasks_completed INT DEFAULT 0,
    tasks_failed INT DEFAULT 0,
    avg_execution_time_ms FLOAT,
    tokens_used INT DEFAULT 0,
    cost_estimate FLOAT DEFAULT 0        -- Costo estimado en USD
);

🔹 Flujo de Memoria


Al iniciar una tarea:

El Orquestador consulta agent_memory para contexto previo del lead.
Si no existe, crea un nuevo registro.


Durante la ejecución:

Cada agente actualiza su context y decisions en tiempo real.


Al completar/fallar:

Se registra el resultado en task_history.
Si el agente aprendió algo nuevo (ej: "El dominio @empresa.com usa este formato de email"), se guarda en learnings.


Optimización:

El Orquestador usa agent_metrics para:

Detectar agentes lentos o con muchos fallos.
Ajustar prioridades (ej: "Usar Hunter.io solo si el dominio es .com.ar").
Cambiar de modelo de IA si el costo es alto.


🤝 6. Contratos entre Agentes
Cada agente debe exponer una interfaz clara para que el Orquestador pueda invocarlo sin acoplamiento.
📌 Estructura de un Contrato
typescript
Copiar

interface AgentContract {
  // Nombre único del agente
  name: string;

  // Descripción de su responsabilidad
  description: string;

  // Entradas esperadas (ej: { leadId: string, industry: string })
  inputSchema: z.ZodSchema;  // Usando Zod para validación

  // Salidas esperadas (ej: { emails: string[], phones: string[] })
  outputSchema: z.ZodSchema;

  // Criterios de éxito (ej: "al menos 2 emails válidos")
  successCriteria: (output: any) => boolean;

  // Máximo de reintentos permitidos
  maxRetries: number;

  // Tiempo máximo de ejecución (ms)
  timeoutMs: number;

  // APIs requeridas (para validar disponibilidad)
  requiredAPIs: string[];

  // Coste estimado por ejecución (tokens o USD)
  estimatedCost: (input: any) => number;
}



🔹 Ejemplo: Contrato del Agente Enriquecedor
typescript
Copiar

const EnriquecedorContract: AgentContract = {
  name: "Enriquecedor",
  description: "Enriquece la ficha de un lead con emails, teléfonos y redes sociales.",
  inputSchema: z.object({
    leadId: z.string(),
    companyName: z.string(),
    website: z.string().url(),
    industry: z.string().optional(),
  }),
  outputSchema: z.object({
    emails: z.array(z.string().email()).min(1),  // Al menos 1 email
    phones: z.array(z.string()).optional(),
    socialMedia: z.record(z.string()).optional(), // { linkedin: "url", twitter: "url" }
    technologies: z.array(z.string()).optional(),
    decisionMakers: z.array(z.object({
      name: z.string(),
      role: z.string(),
      email: z.string().email().optional(),
    })).optional(),
    confidenceScore: z.number().min(0).max(100), // 0-100%
  }),
  successCriteria: (output) => output.emails.length >= 1 && output.confidenceScore >= 60,
  maxRetries: 3,
  timeoutMs: 60000, // 1 minuto
  requiredAPIs: ["Hunter", "Firecrawl", "GooglePlaces"],
  estimatedCost: (input) => {
    // Coste estimado: 1 llamada a Hunter + 1 a Firecrawl = ~$0.01
    return 0.01;
  },
};



🔹 Comunicación entre Agentes

Patrón: Event-Driven (basado en eventos).
Implementación:

Usar Neon PostgreSQL como cola de eventos (tabla agent_events).
Cada agente publica eventos al completar una tarea.
El Orquestador suscribe a eventos y delega nuevas tareas.

  timestamp: Date;
  metadata: {
    taskId?: string;
    leadId?: string;
    retries?: number;
  };
}

🔍 10. Respuestas a las Preguntas para Claude
1. ¿Qué agentes faltan?
✅ Agentes propuestos adicionales:

InvestigadorDeMercado: Para analizar tendencias antes de definir el ICP (usando Google Trends, SEMrush alternativas gratuitas).
DetectarOportunidades: Analiza el sitio web del prospecto para identificar dolores específicos (ej: "No tiene chatbot", "Su web es lenta").
GeneradorDeValorPreContacto: Crea un diagnóstico gratuito o mini-auditoría para enviar antes del primer email (aumenta tasa de respuesta).
GestorDeReuniones: Agenda reuniones automáticamente (integración con Google Calendar).
AnalistaDeCompetencia: Investiga competidores del prospecto para personalizar propuestas.
2. ¿Qué responsabilidades deberían fusionarse?
🔹 Fusionar:

Copywriter + GeneradorDePropuestas → GeneradorDeContenido (ambos generan texto, pero para distintos fines).
Seguimiento + Negociador → GestorDeOportunidades (ambos trabajan en la misma etapa del pipeline).
🔹 No fusionar:

Enriquecedor debe permanecer separado (su responsabilidad es muy específica).
Conversacional debe ser independiente (requiere manejo de contexto en tiempo real).
3. ¿Qué agentes deberían dividirse?
🔹 Dividir Enriquecedor en:

EnriquecedorDeContactos: Solo busca emails, teléfonos y redes sociales.
EnriquecedorDeContexto: Analiza el sitio web, tecnologías y datos comerciales.
🔹 Dividir AnalistaWeb en:

AnalistaTecnico: SEO, rendimiento, tecnologías (Lighthouse, Wappalyzer).
AnalistaComercial: Oportunidades de venta, dolores, competencia.
4. ¿Qué patrones MDR (Model-Driven Reasoning) recomienda?
🔹 Patrones a implementar:

Chain-of-Thought (CoT): Para agentes que requieren razonamiento paso a paso (ej: Estratega).
ReAct (Reason + Act): Para agentes que interactúan con APIs externas (ej: Enriquecedor).
Reflexión: El agente evalúa su propio trabajo antes de reportar (ej: Copywriter revisa si el email suena natural).
Multi-Agent Debate: Varios agentes discuten la mejor estrategia (ej: Orquestador consulta a Estratega y AnalistaComercial antes de decidir cómo contactar un lead).

5. ¿Qué arquitectura de memoria compartida recomienda?
🔹 Recomendación:

Base de datos relacional (Neon PostgreSQL) para datos estructurados (leads, tareas, métricas).
Tabla agent_memory con campos JSONB para contexto flexible.
Índices optimizados para búsquedas rápidas (ej: lead_id, agent_name).
Limpieza automática de memoria antigua (borrar contexto de leads >30 días sin actividad).
🔹 Alternativa para memoria vectorial (si se necesita búsqueda semántica):

Qdrant (open-source, deployable en Vercel o Replit).
Usar para:

Buscar leads similares (ej: "Encontrar empresas como X").
Recuperar contexto de conversaciones pasadas.

6. ¿Qué protocolos de comunicación entre agentes son más adecuados?
🔹 Recomendación: Event-Driven + Cola de Tareas

Neon PostgreSQL como cola de eventos (tabla agent_events).
El Orquestador actúa como "broker":

Publica tareas en la cola.
Los agentes suscriben a eventos relevantes.
Cada agente actualiza el estado de su tarea.

🔹 Ventajas:

Desacoplamiento total: Los agentes no se llaman entre sí directamente.
Escalabilidad: Se pueden añadir más agentes sin modificar el sistema.
Persistencia: Las tareas no se pierden si un agente falla.

7. ¿Cómo implementar bucles autónomos seguros?
🔹 Mecanismos de seguridad:

Límites de reintentos (maxRetries por agente).
Timeouts (timeoutMs por tarea).
Presupuesto por tarea (el Orquestador rechaza tareas si el costo estimado supera el límite).
Detección de bucles (el Orquestador monitorea dependencias circulares).
Circuito breaker (si una API falla 3 veces seguidas, se desactiva temporalmente).

class SafeAgentExecutor {
  constructor(
    private agent: Agent,
    private maxRetries: number,
    private timeoutMs: number,
    private maxCost: number
  ) {}

  async execute(task: Task): Promise<Result> {
    let retries = 0;
    let lastError: Error | null = null;

    while (retries < this.maxRetries) {
      try {
        const startTime = Date.now();
        const costEstimate = this.agent.estimatedCost(task.input);

        if (costEstimate > this.maxCost) {
          throw new Error(`Cost ${costEstimate} exceeds budget ${this.maxCost}`);
        }

        const result = await Promise.race([
          this.agent.run(task),
          new Promise((_, reject) =>
            setTimeout(() => reject(new Error("Timeout")), this.timeoutMs)
          ),
        ]);

        if (this.agent.successCriteria(result)) {
          return result;
        } else {
          throw new Error("Success criteria not met");
        }
      } catch (error) {
        lastError = error;
        retries++;
        await this.sleep(1000 * retries); // Espera exponencial
      }
    }

    throw new Error(`Max retries (${this.maxRetries}) exceeded. Last error: ${lastError?.message}`);
  }

  private sleep(ms: number) {
    return new Promise(resolve => setTimeout(resolve, ms));
  }
}



8. ¿Cómo evitar ciclos infinitos?
🔹 Soluciones:


Grafo acíclico de dependencias:

El Orquestador valida que no haya ciclos antes de asignar tareas.
Ejemplo: Si AgenteA depende de AgenteB y AgenteB depende de AgenteA, el Orquestador rechaza la tarea.


Límites de profundidad:

Cada tarea tiene un campo depth (profundidad en la cadena de dependencias).
Si depth > 10, el Orquestador detiene la ejecución.


Tiempo máximo de ejecución global:

Una tarea no puede ejecutarse por más de 24 horas (configurable).


Detección de patrones repetitivos:

Si un agente repite la misma acción 3 veces seguidas con el mismo input, el Orquestador interviene.

🔹 Componentes Clave para Escalabilidad


Multi-Tenancy (Multi-Empresa):

Cada cliente (tenant) tiene su propio espacio aislado en Neon.
Usar tenant_id en todas las tablas para separar datos.


API Gateway (Vercel):

Ruta todas las peticiones a los microservicios correspondientes.
Autenticación: JWT con tenant_id para identificar al cliente.


Orquestador por Tenant:

Cada cliente tiene su propio Orquestador (instancia lógica, no física).
Comparten el mismo código, pero con configuración y memoria separadas.


Cola de Tareas Distribuida:

Usar Neon PostgreSQL como cola distribuida (tabla tasks).
Los agentes compiten por tareas (patrón "competing consumers").


Autoescalado:

Vercel escala automáticamente las API Routes.
Neon escala la base de datos según la carga.


Cache:

Vercel Cache para respuestas frecuentes (ej: lista de leads de un cliente).
Redis (opcional) para caché de alto rendimiento.


Monitoreo:

Sentry para errores.
Langfuse para tracing de agentes IA.
Neon Metrics para consultas a la base de datos.

Definir el contrato (en packages/shared/contracts/Prospector.ts):

import { z } from "zod";

export const ProspectorContract = {
  name: "Prospector",
  description: "Busca empresas en una industria y ubicación específicas.",
  inputSchema: z.object({
    industry: z.string(),
    location: z.string(),
    limit: z.number().default(10),
  }),
  outputSchema: z.object({
    companies: z.array(
      z.object({
        name: z.string(),
        address: z.string(),
        website: z.string().url().nullable(),
        phone: z.string().nullable(),
        placeId: z.string(),
      })
    ),
  }),
  successCriteria: (output) => output.companies.length >= 1,
  maxRetries: 2,
  timeoutMs: 30000,
  requiredAPIs: ["GooglePlaces"],
  estimatedCost: () => 0.005, // ~$0.005 por búsqueda
};





Implementar el agente (en apps/orchestrator/src/agents/Prospector.ts):
typescript
Copiar

import { ProspectorContract } from "@clientum/shared/contracts";
import { Agent } from "@clientum/agents-sdk";
import { googlePlacesClient } from "../clients/googlePlaces";

export class Prospector extends Agent<typeof ProspectorContract> {
  constructor() {
    super(ProspectorContract);
  }

  async run(task: any) {
    const { industry, location, limit } = task.input;

    // Llamar a Google Places API
    const companies = await googlePlacesClient.search({
      query: `${industry} in ${location}`,
      radius: 50000, // 50km
    });

    // Filtrar y limitar resultados
    const filtered = companies
      .filter((c) => c.website || c.phone)
      .slice(0, limit);

    return {
      companies: filtered.map((c) => ({
        name: c.name,
        address: c.vicinity,
        website: c.website,
        phone: c.formatted_phone_number,
        placeId: c.place_id,
      })),
    };
  }
}





Registrar el agente en el Orquestador (en apps/orchestrator/src/index.ts):

7Visión Final – Clientum AI Sales Operating
System
Clientum no debe ser un CRM con inteligencia artificial ni un conjunto de herramientas. Debe
convertirse en un Sistema Operativo de Ventas B2B Autónomo.
El usuario solo interactúa con un único agente: el Orquestador.
El Orquestador recibe objetivos de negocio, por ejemplo:
Conseguir 20 reuniones con distribuidoras de generadores.
Vender $5.000.000 en servicios este mes.
Abrir mercado en una nueva industria.
A partir de ese objetivo, planifica el trabajo, crea tareas, asigna agentes, controla el avance, replanifica
cuando es necesario y mide los resultados. Ningún otro agente requiere interacción humana.
Los agentes especializados cubren todo el ciclo comercial:
Inteligencia de mercado.
Estrategia y Buyer Persona.
Prospección.
Enriquecimiento de datos.
Investigación profunda de empresas y decisores.
Calificación y scoring.
Generación de valor personalizada.
Creación de propuestas y brochures.
Generación de campañas.
Outreach multicanal (email, WhatsApp y otros canales disponibles).
Gestión de conversaciones.
Seguimiento automático.
Negociación.
Cierre comercial.
Onboarding.
Customer Success.
Upselling.
Cross-selling.
Solicitud de referidos.
Aprendizaje continuo.
Todos los agentes trabajan de forma autónoma siguiendo el mismo ciclo:
Planificar → Ejecutar → Validar → Reintentar → Reportar → Aprender
Cada agente continúa trabajando hasta cumplir el objetivo asignado o hasta alcanzar los límites
definidos por el Orquestador.

Intervención humana
La intervención humana debe ser mínima.
El sistema debe intentar resolver todo el proceso comercial por sí mismo.
Solo solicitará la participación de un colaborador cuando detecte que es indispensable, por ejemplo:
Reuniones de descubrimiento.
Definición de requerimientos.
Validaciones técnicas complejas.
Aprobaciones comerciales fuera de las reglas configuradas.

El objetivo del proyecto no es automatizar tareas aisladas.

📄 CLIENTUM AI SALES OPERATING SYSTEM
🔷 DOCUMENTO MAESTRO DE ARQUITECTURA, AGENTES IA Y ROADMAP TÉCNICO
Versión Final Consolidada para Revisión por Claude/Klaus (Reply) – 17/07/2026
🎯 1. VISIÓN ESTRATÉGICA
Clientum es un Sistema Operativo Comercial Autónomo B2B donde agentes de IA especializados trabajan coordinados por un Orquestador central, capaz de gestionar el ciclo comercial completo (desde prospección hasta crecimiento de cuentas) sin intervención humana constante.
📌 Objetivos Clave
✅ Automatizar el 95% del proceso comercial (solo intervención humana en reuniones técnicas o decisiones estratégicas).
✅ Escalar como SaaS multi-tenant (varios clientes usando la misma plataforma de forma aislada).
✅ Aprender y optimizarse con cada interacción (memoria compartida + aprendizaje continuo).
✅ Mantener costos bajos (priorizar APIs gratuitas y open-source).
✅ Desplegarse en el stack: Replit → GitHub → Vercel → Neon.
🔹 Principios Fundamentales

Arquitectura orientada a agentes: Cada agente tiene una única responsabilidad.
Comunicación por eventos: Los agentes se comunican mediante colas de tareas (Neon PostgreSQL).
Bucles autónomos seguros: Cada agente sigue el ciclo:
Planificar → Ejecutar → Validar → Reintentar → Reportar → Aprender.
Multi-tenant desde el día 1: Datos aislados por tenant_id en Neon.
APIs desacopladas: El Orquestador puede cambiar de proveedor sin afectar al resto.
Memoria persistente: Todo el contexto se guarda en Neon PostgreSQL.

-- Tabla principal de memoria por agente
CREATE TABLE agent_memory (
    id SERIAL PRIMARY KEY,
    tenant_id VARCHAR(50) NOT NULL,       -- Para multi-tenant
    agent_name VARCHAR(50) NOT NULL,       -- Ej: "Enriquecedor"
    lead_id VARCHAR(100),                  -- ID del lead (opcional)
    conversation_id VARCHAR(100),          -- ID de la conversación (opcional)
    context JSONB NOT NULL,                -- Contexto acumulado
    decisions JSONB,                       -- Decisiones tomadas
    learnings JSONB,                       -- Aprendizajes (patrones)
    metadata JSONB,                        -- Metadatos adicionales
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW(),
    UNIQUE(tenant_id, agent_name, lead_id)
);

-- Tabla de historial de tareas
CREATE TABLE task_history (
    id SERIAL PRIMARY KEY,
    tenant_id VARCHAR(50) NOT NULL,
    task_id VARCHAR(100) NOT NULL,
    agent_name VARCHAR(50) NOT NULL,
    status VARCHAR(20) NOT NULL,           -- "pending", "in_progress", "completed", "failed"
    input_data JSONB NOT NULL,
    output_data JSONB,
    retries INT DEFAULT 0,
    error_message TEXT,
    tokens_used INT DEFAULT 0,
    api_calls JSONB,                        -- Registrar qué APIs se usaron
    start_time TIMESTAMP DEFAULT NOW(),
    end_time TIMESTAMP,
    cost_estimate FLOAT DEFAULT 0        -- Costo en USD
);

-- Tabla de métricas por agente
CREATE TABLE agent_metrics (
    id SERIAL PRIMARY KEY,
    tenant_id VARCHAR(50) NOT NULL,
    agent_name VARCHAR(50) NOT NULL,
    date DATE NOT NULL,
    tasks_completed INT DEFAULT 0,
    tasks_failed INT DEFAULT 0,
    avg_execution_time_ms FLOAT,
    tokens_used INT DEFAULT 0,
    cost_estimate FLOAT DEFAULT 0,
    UNIQUE(tenant_id, agent_name, date)
);

-- Tabla de leads (CRM)
CREATE TABLE leads (
    id SERIAL PRIMARY KEY,
    tenant_id VARCHAR(50) NOT NULL,
    company_name VARCHAR(200) NOT NULL,
    website VARCHAR(500),
    emails TEXT[],
    phones TEXT[],
    industry VARCHAR(100),
    status VARCHAR(50) DEFAULT 'prospeccion', -- prospeccion, contacto, negociacion, cerrado, perdido
    score INT DEFAULT 0,                     -- 0-100 (calidad del lead)
    last_contact TIMESTAMP,
    next_follow_up TIMESTAMP,
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

-- Tabla de conversaciones
CREATE TABLE conversations (
    id SERIAL PRIMARY KEY,
    tenant_id VARCHAR(50) NOT NULL,
    lead_id INT REFERENCES leads(id),
    channel VARCHAR(20) NOT NULL,          -- "email", "whatsapp", "linkedin"
    messages JSONB NOT NULL,               -- [{ role: "user" | "agent", content: string, timestamp: TIMESTAMP }]
    status VARCHAR(20) DEFAULT 'active',   -- "active", "closed", "waiting_response"
    context JSONB,                          -- Contexto de la conversación
    created_at TIMESTAMP DEFAULT NOW(),
    updated_at TIMESTAMP DEFAULT NOW()
);

🔹 Flujo de Memoria


Al iniciar una tarea:

El Orquestador consulta agent_memory para contexto previo del lead.
Si no existe, crea un nuevo registro.


Durante la ejecución:

Cada agente actualiza su context y decisions en tiempo real.


Al completar/fallar:

Se registra el resultado en task_history.
Si el agente aprendió algo nuevo (ej: "El dominio @empresa.com usa este formato de email"), se guarda en learnings.


Optimización:

El Orquestador usa agent_metrics para:

Detectar agentes lentos o con muchos fallos.
Ajustar prioridades (ej: "Usar Hunter.io solo si el dominio es .com.ar").
Cambiar de modelo de IA si el costo es alto.

interface AgentContract {
  name: string;                     // Nombre único del agente
  description: string;              // Descripción de su responsabilidad
  inputSchema: z.ZodSchema;        // Entradas esperadas (validación con Zod)
  outputSchema: z.ZodSchema;       // Salidas esperadas
  successCriteria: (output: any) => boolean; // Criterios de éxito
  maxRetries: number;               // Máximo de reintentos
  timeoutMs: number;                // Tiempo máximo de ejecución (ms)
  requiredAPIs: string[];            // APIs requeridas
  estimatedCost: (input: any) => number; // Coste estimado (USD o tokens)
}

import { z } from "zod";

export const ProspectorContract: AgentContract = {
  name: "Prospector",
  description: "Busca empresas en una industria y ubicación específicas.",
  inputSchema: z.object({
    industry: z.string().min(1),
    location: z.string().min(1),
    limit: z.number().int().positive().default(10),
    radius: z.number().int().positive().default(50000), // 50km
  }),
  outputSchema: z.object({
    companies: z.array(
      z.object({
        name: z.string(),
        address: z.string(),
        website: z.string().url().nullable(),
        phone: z.string().nullable(),
        placeId: z.string(),
        latitude: z.number().nullable(),
        longitude: z.number().nullable(),
      })
    ).min(1), // Al menos 1 empresa
  }),
  successCriteria: (output) => output.companies.length >= 1,
  maxRetries: 2,
  timeoutMs: 30000, // 30 segundos
  requiredAPIs: ["GooglePlaces"],
  estimatedCost: () => 0.005, // ~$0.005 por búsqueda
};

export const EnriquecedorContract: AgentContract = {
  name: "Enriquecedor",
  description: "Enriquece la ficha de un lead con emails, teléfonos y datos públicos.",
  inputSchema: z.object({
    leadId: z.string(),
    companyName: z.string(),
    website: z.string().url(),
    industry: z.string().optional(),
    location: z.string().optional(),
  }),
  outputSchema: z.object({
    emails: z.array(z.string().email()).min(1), // Al menos 1 email
    phones: z.array(z.string()).optional(),
    socialMedia: z.record(z.string()).optional(), // { linkedin: "url", twitter: "url" }
    domainInfo: z.object({
      registrar: z.string().optional(),
      creationDate: z.string().optional(),
      expirationDate: z.string().optional(),
    }).optional(),
    technologies: z.array(z.string()).optional(),
    decisionMakers: z.array(
      z.object({
        name: z.string(),
        role: z.string(),
        email: z.string().email().optional(),
        linkedin: z.string().url().optional(),
      })
    ).optional(),
    confidenceScore: z.number().min(0).max(100), // 0-100%
  }),
  successCriteria: (output) => output.emails.length >= 1 && output.confidenceScore >= 60,
  maxRetries: 3,
  timeoutMs: 60000, // 1 minuto
  requiredAPIs: ["Hunter", "Firecrawl", "GooglePlaces"],
  estimatedCost: (input) => {
    // Coste: 1 Hunter + 1 Firecrawl = ~$0.01
    return 0.01;
  },
};

      Problema
      Solución
      Implementación
    
  
  
    
      Tarea en bucle infinito
      Límites de reintentos (maxRetries)
      Cada agente define su maxRetries (ej: 3)
    
    
      Dependencias circulares
      Grafo acíclico de tareas
      El Orquestador valida dependencias antes de asignar
    
    
      Bloqueo por APIs externas
      Timeouts por agente
      timeoutMs en el contrato (ej: 60s)
    
    
      Memoria infinita
      Límite de contexto por lead
      Borrar contexto antiguo (>30 días)
    
    
      Coste descontrolado
      Presupuesto por tarea
      Orquestador rechaza tareas si estimatedCost > presupuesto

class SafeAgentExecutor {
  constructor(
    private agent: Agent,
    private maxRetries: number,
    private timeoutMs: number,
    private maxCost: number
  ) {}

  async execute(task: Task, context: AgentContext): Promise<Result> {
    let retries = 0;
    let lastError: Error | null = null;

    while (retries < this.maxRetries) {
      try {
        const costEstimate = this.agent.contract.estimatedCost(task.input);
        if (costEstimate > this.maxCost) {
          throw new Error(`Cost ${costEstimate} exceeds budget ${this.maxCost}`);
        }

        const result = await Promise.race([
          this.agent.run(task, context),
          new Promise((_, reject) =>
            setTimeout(() => reject(new Error("Timeout")), this.timeoutMs)
          ),
        ]);

        if (this.agent.contract.successCriteria(result)) {
          return result;
        } else {
          throw new Error("Success criteria not met");
        }
      } catch (error) {
        lastError = error as Error;
        retries++;
        await this.sleep(1000 * retries); // Espera exponencial
        context.log(`Retry ${retries}/${this.maxRetries}: ${lastError.message}`);
      }
    }

    throw new Error(`Max retries (${this.maxRetries}) exceeded. Last error: ${lastError?.message}`);
  }

  private sleep(ms: number): Promise<void> {
    return new Promise(resolve => setTimeout(resolve, ms));
  }
}

import { Agent } from "@clientum/agents-sdk";
import { NeonClient } from "@clientum/shared/db";
import { Task } from "@clientum/shared/types";

export class Orquestador {
  private agents: Record<string, Agent>;
  private db: NeonClient;
  private maxRetries: number = 3;
  private timeoutMs: number = 60000;

  constructor(agents: Record<string, Agent>) {
    this.agents = agents;
    this.db = new NeonClient();
  }

  async createTask(task: Omit<Task, "id" | "status" | "createdAt">): Promise<Task> {
    const newTask = await this.db.task.create({
      data: {
        ...task,
        status: "pending",
        retries: 0,
        createdAt: new Date(),
      },
    });
    return newTask;
  }

  async assignTask(taskId: string): Promise<void> {
    const task = await this.db.task.findUnique({ where: { id: taskId } });
    if (!task) throw new Error("Task not found");

    const agent = this.agents[task.agentName];
    if (!agent) throw new Error(`Agent ${task.agentName} not found`);

    try {
      const result = await agent.run(task);
      await this.db.task.update({
        where: { id: taskId },
        data: {
          status: "completed",
          output: result,
          endTime: new Date(),
        },
      });
      await this.publishEvent({
        type: "task_completed",
        agent: task.agentName,
        data: result,
        metadata: { taskId: task.id },
      });
    } catch (error) {
      const retries = task.retries + 1;
      if (retries >= this.maxRetries) {
        await this.db.task.update({
          where: { id: taskId },
          data: {
            status: "failed",
            error: error.message,
            endTime: new Date(),
          },
        });
        await this.publishEvent({
          type: "task_failed",
          agent: task.agentName,
          data: { error: error.message },
          metadata: { taskId: task.id, retries },
        });
      } else {
        await this.db.task.update({
          where: { id: taskId },
          data: { retries, status: "retrying" },
        });
        // Reintentar después de un delay exponencial
        setTimeout(() => this.assignTask(taskId), 1000 * retries);
      }
    }
  }

  private async publishEvent(event: AgentEvent): Promise<void> {
    await this.db.agentEvent.create({ data: event });
    // Notificar a suscriptores (ej: frontend en tiempo real)

import { Agent } from "@clientum/agents-sdk";
import { ProspectorContract } from "@clientum/shared/contracts";
import { googlePlacesClient } from "../clients/googlePlaces";

export class Prospector extends Agent<typeof ProspectorContract> {
  constructor() {
    super(ProspectorContract);
  }

  async run(task: any, context: AgentContext): Promise<any> {
    const { industry, location, limit, radius } = task.input;

    context.log(`Buscando ${limit} empresas de ${industry} en ${location}...`);

    // Llamar a Google Places API
    const companies = await googlePlacesClient.search({
      query: `${industry} in ${location}`,
      radius,
      type: "establishment", // Filtrar por negocios
    });

    // Filtrar empresas con sitio web o teléfono
    const filtered = companies
      .filter((c) => c.website || c.formatted_phone_number)
      .slice(0, limit);

    if (filtered.length === 0) {
      throw new Error(`No se encontraron empresas de ${industry} en ${location}`);
    }

    // Guardar empresas en Neon (estado: "raw")
    const createdCompanies = await Promise.all(
      filtered.map((c) =>
        context.db.company.upsert({
          where: { placeId: c.place_id },
          create: {
            name: c.name,
            address: c.vicinity,
            website: c.website,
            phone: c.formatted_phone_number,
            placeId: c.place_id,
            latitude: c.geometry?.location?.lat,
            longitude: c.geometry?.location?.lng,
            status: "raw",
            industry,
            location,
          },
          update: {
            name: c.name,
            address: c.vicinity,
            website: c.website,
            phone: c.formatted_phone_number,
            latitude: c.geometry?.location?.lat,
            longitude: c.geometry?.location?.lng,
          },
        })
      )
    );

    return {
      companies: createdCompanies.map((c) => ({
        id: c.id,
        name: c.name,
        address: c.address,
        website: c.website,
        phone: c.phone,
        placeId: c.placeId,
      })),
    };
  }
}

import { Agent } from "@clientum/agents-sdk";
import { EnriquecedorContract } from "@clientum/shared/contracts";
import { hunterClient } from "../clients/hunter";
import { firecrawlClient } from "../clients/firecrawl";

export class Enriquecedor extends Agent<typeof EnriquecedorContract> {
  constructor() {
    super(EnriquecedorContract);
  }

  async run(task: any, context: AgentContext): Promise<any> {
    const { leadId, companyName, website, industry } = task.input;

    context.log(`Enriqueciendo lead ${leadId} (${companyName})...`);

    // 1. Buscar emails con Hunter.io
    let emails: string[] = [];
    try {
      const hunterResult = await hunterClient.findEmails({
        domain: new URL(website).hostname,
        company: companyName,
      });
      emails = hunterResult.emails?.map((e) => e.value) || [];
    } catch (error) {
      context.log(`Hunter falló para ${website}: ${error.message}`);
    }

    // 2. Scrapear sitio web con Firecrawl
    let scrapedData: any = null;
    try {
      scrapedData = await firecrawlClient.scrape(website, {
        formats: ["markdown"],
      });
    } catch (error) {
      context.log(`Firecrawl falló para ${website}: ${error.message}`);
    }

    // 3. Buscar teléfonos en el sitio (regex)
    const phones: string[] = [];
    if (scrapedData?.markdown) {
      const phoneRegex = /(\+?\d{1,3}[-.\s]?)?\(?\d{3}\)?[-.\s]?\d{3}[-.\s]?\d{4}/g;
      const foundPhones = scrapedData.markdown.match(phoneRegex) || [];
      phones.push(...foundPhones.filter((p) => !phones.includes(p)));
    }

    // 4. Buscar redes sociales (simplificado)
    const socialMedia: Record<string, string> = {};
    if (scrapedData?.markdown) {
      const socialLinks = scrapedData.markdown.match(/https?:\/\/(www\.)?(linkedin|twitter|facebook|instagram)\.com\/[a-zA-Z0-9(\-_@.)]+\/?/g) || [];
      socialLinks.forEach((link) => {
        if (link.includes("linkedin")) socialMedia.linkedin = link;
        if (link.includes("twitter")) socialMedia.twitter = link;
        if (link.includes("facebook")) socialMedia.facebook = link;
        if (link.includes("instagram")) socialMedia.instagram = link;
      });
    }

    // 5. Calcular confidence score (0-100)
    let confidenceScore = 50; // Base
    if (emails.length >= 1) confidenceScore += 20;
    if (phones.length >= 1) confidenceScore += 15;
    if (socialMedia.linkedin) confidenceScore += 10;
    if (scrapedData) confidenceScore += 15;

    // Actualizar lead en Neon
    await context.db.company.update({
      where: { id: leadId },
      data: {
        emails,
        phones,
        socialMedia,
        scrapedData: scrapedData?.markdown,
        confidenceScore,
        status: "enriched",
        updatedAt: new Date(),
      },
    });

    return {
      emails,
      phones,
      socialMedia,
      confidenceScore,
    };
  }
}

const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY);

// clients/googlePlaces.js
import axios from "axios";

const API_KEY = process.env.GOOGLE_PLACES_API_KEY;
const BASE_URL = "https://maps.googleapis.com/maps/api/place";

export const googlePlacesClient = {
  /**
   * Busca empresas por texto
   * @param {object} params - Parámetros de búsqueda
   * @param {string} params.query - Consulta de búsqueda (ej: "distribuidoras de generadores")
   * @param {string} params.location - Ubicación (lat,lng)
   * @param {number} params.radius - Radio en metros (máx 50000)
   * @returns {Promise<Array>} - Lista de empresas
   */
  async textSearch({ query, location, radius = 50000 }) {
    try {
      const response = await axios.get(`${BASE_URL}/textsearch/json`, {
        params: {
          query,
          location,
          radius,
          type: "establishment",
          key: API_KEY,
        },
      });
      return response.data.results || [];
    } catch (error) {
      console.error("Error en Google Places Text Search:", error.message);
      throw error;
    }
  },

  /**
   * Obtiene detalles de un lugar
   */
  async getPlaceDetails(placeId) {
    try {
      const response = await axios.get(`${BASE_URL}/details/json`, {
        params: {
          place_id: placeId,
          key: API_KEY,
        },
      });
      return response.data.result || null;
    } catch (error) {
      console.error("Error en Google Places Details:", error.message);
      throw error;
    }
  },
};

// clients/firecrawl.js
import axios from "axios";

const API_KEY = process.env.FIRECRAWL_API_KEY;
const BASE_URL = "https://api.firecrawl.dev/v0";

export const firecrawlClient = {
  /**
   * Scrapea una URL
   * @param {string} url - URL a scrapear
   * @param {object} options - Opciones de scraping
   * @returns {Promise<object>} - Datos scrapeados
   */
  async scrape(url, options = {}) {
    try {
      const response = await axios.post(`${BASE_URL}/scrape`, {
        url,
        formats: ["markdown"],
        ...options,
      }, {
        headers: {
          "Authorization": `Bearer ${API_KEY}`,
          "Content-Type": "application/json",
        },
      });
      return response.data.data || {};
    } catch (error) {
      console.error("Error en Firecrawl:", error.message);
      throw error;
    }
  },

  /**
   * Scrapea múltiples URLs
   */
  async batchScrape(urls, options = {}) {
    try {
      const response = await axios.post(`${BASE_URL}/batch`, {
        urls: urls.map(url => ({ url, ...options })),
      }, {
        headers: {
          "Authorization": `Bearer ${API_KEY}`,
          "Content-Type": "application/json",
        },
      });
      return response.data.data || [];
    } catch (error) {
      console.error("Error en Firecrawl Batch:", error.message);
      throw error;
    }
  },
};

export const gmailClient = {
  /**
   * Inicializa el cliente de Gmail con el token
   */
  async init(token) {
    oauth2Client.setCredentials(token);
    return google.gmail({ version: "v1", auth: oauth2Client });
  },

  /**
   * Envía un email
   */
  async sendEmail({ to, subject, body, from }) {
    const gmail = await this.init();
    const raw = this.makeRawEmail({ to, subject, body, from });

    try {
      const response = await gmail.users.messages.send({
        userId: "me",
        requestBody: { raw },
      });
      return response.data;
    } catch (error) {
      console.error("Error al enviar email:", error.message);
      throw error;
    }
  },

  /**
   * Convierte un email a formato raw (base64)
   */
  makeRawEmail({ to, subject, body, from }) {
    const email = [
      `From: ${from}`,
      `To: ${to}`,
      `Subject: ${subject}`,
      "MIME-Version: 1.0",
      "Content-Type: text/plain; charset=utf-8",
      "",
      body,
    ].join("\n");

    return Buffer.from(email).toString("base64").replace(/\+/g, "-").replace(/\//g, "_");
  },

  /**

   */
  async listUnreadEmails() {
    const gmail = await this.init();

      });

  'prospeccion': prospeccionAction,

/**
 * Carga la ficha de un agente desde su carpeta
 */
async function loadAgentSlug(slug) {
  const [department, name] = slug.split('/');
  const agentDir = join(__dirname, '..', 'agentes', department, name);

  try {
    const files = await readdir(agentDir);
    const agent = {};

    for (const file of files) {
      if (file.endsWith('.md')) {
        const content = await readFile(join(agentDir, file), 'utf8');
        agent[file.replace('.md', '')] = content;
      }
    }

    return {
      slug,
      department,
      name,
      ...agent,
    };
  } catch (error) {
    console.error(`❌ No se encontró el agente ${slug}:`, error.message);
    return null;
  }
}

/**
 * Ejecuta una acción de un agente
 */
async function executeAgent(agent, task) {
  const action = agentActions[agent.department] || defaultAction;
  const context = {
    prisma,
    gemini: geminiClient,
    googlePlaces: googlePlacesClient,
    hunter: hunterClient,
    firecrawl: firecrawlClient,
    log: (message) => console.log(`[${agent.slug}] ${message}`),
  };

  try {
    const result = await action(agent, task.input, context);
    return { success: true, data: result };
  } catch (error) {
    console.error(`❌ Error en ${agent.slug}:`, error.message);
    return { success: false, error: error.message };
  }
}

/**
 * Acción para el agente de Prospección
 */
async function prospeccionAction(agent, input, context) {
  const { industry, location, limit = 10 } = input;

  context.log(`Buscando ${limit} empresas de ${industry} en ${location}...`);

  // 1. Buscar en Google Places
  const companies = await context.googlePlaces.textSearch({
    query: `${industry} in ${location}`,
    radius: 50000,
  });

  // 2. Filtrar empresas con sitio web o teléfono
  const filtered = companies
    .filter(c => c.website || c.formatted_phone_number)
    .slice(0, limit);

  if (filtered.length === 0) {
    throw new Error(`No se encontraron empresas de ${industry} en ${location}`);
  }

  // 3. Guardar en Neon
  const createdCompanies = await Promise.all(
    filtered.map(async (c) => {
      return prisma.company.upsert({
        where: { placeId: c.place_id },
        create: {
          name: c.name,
          address: c.vicinity,
          website: c.website,
          phone: c.formatted_phone_number,
          placeId: c.place_id,
          latitude: c.geometry?.location?.lat,
          longitude: c.geometry?.location?.lng,
          status: "raw",
          industry,
          location,
        },
        update: {
          name: c.name,
          address: c.vicinity,
          website: c.website,
          phone: c.formatted_phone_number,
          latitude: c.geometry?.location?.lat,
          longitude: c.geometry?.location?.lng,
        },
      });
    })
  );

  return {
    companies: createdCompanies.map(c => ({
      id: c.id,
      name: c.name,
      website: c.website,
      phone: c.phone,
    })),
    count: createdCompanies.length,
  };
}

/**
 * Acción para el agente de Enriquecimiento
 */
async function enriquecimientoAction(agent, input, context) {
  const { leadId, companyName, website } = input;

  context.log(`Enriqueciendo lead ${leadId} (${companyName})...`);

  // 1. Buscar emails con Hunter.io
  let emails = [];
  try {
    const domain = new URL(website).hostname;
    const hunterResult = await context.hunter.findEmails({ domain, company: companyName });
    emails = hunterResult.emails?.map(e => e.value) || [];
  } catch (error) {
    context.log(`Hunter falló para ${website}: ${error.message}`);
  }

  // 2. Scrapear sitio web con Firecrawl
  let scrapedData = null;
  try {
    scrapedData = await context.firecrawl.scrape(website, {
      formats: ["markdown"],
    });
  } catch (error) {
    context.log(`Firecrawl falló para ${website}: ${error.message}`);
  }

  // 3. Buscar teléfonos en el sitio (regex)
  const phones = [];
  if (scrapedData?.markdown) {
    const phoneRegex = /(\+?\d{1,3}[-.\s]?)?\(?\d{3}\)?[-.\s]?\d{3}[-.\s]?\d{4}/g;
    const foundPhones = scrapedData.markdown.match(phoneRegex) || [];
    phones.push(...foundPhones.filter(p => !phones.includes(p)));
  }

  // 4. Buscar redes sociales
  const socialMedia = {};
  if (scrapedData?.markdown) {
    const socialLinks = scrapedData.markdown.match(/https?:\/\/(www\.)?(linkedin|twitter|facebook|instagram)\.com\/[a-zA-Z0-9(\-_@.)]+\/?/g) || [];
    socialLinks.forEach(link => {
      if (link.includes("linkedin")) socialMedia.linkedin = link;
      if (link.includes("twitter")) socialMedia.twitter = link;
      if (link.includes("facebook")) socialMedia.facebook = link;
      if (link.includes("instagram")) socialMedia.instagram = link;
    });
  }

  // 5. Calcular confidence score (0-100)
  let confidenceScore = 50;
  if (emails.length >= 1) confidenceScore += 20;
  if (phones.length >= 1) confidenceScore += 15;
  if (socialMedia.linkedin) confidenceScore += 10;
  if (scrapedData) confidenceScore += 15;

  // 6. Actualizar lead en Neon
  await prisma.company.update({
    where: { id: leadId },
    data: {
      emails,
      phones,
      socialMedia,
      scrapedData: scrapedData?.markdown,
      confidenceScore,
      status: "enriched",
      updatedAt: new Date(),
    },
  });

  return {
    emails,
    phones,
    socialMedia,
    confidenceScore,
  };
}

async function analistaWebAction(agent, input, context) {
  const { leadId, website } = input;

  context.log(`Analizando sitio web de ${website}...`);

  // 1. Scrapear con Firecrawl
  const scrapedData = await context.firecrawl.scrape(website);

  // 2. Analizar con Lighthouse (opcional, requiere Node.js 18+)
  // const lighthouse = await context.lighthouse.analyze(website);

  // 3. Detectar tecnologías con Wappalyzer (simplificado)

  if (scrapedData.markdown) {

    if (scrapedData.markdown.includes("Shopify")) technologies.push("Shopify");
    if (scrapedData.markdown.includes("React")) technologies.push("React");
  }

  // 4. Identificar oportunidades
  const oportunidades = [];
  if (!scrapedData.markdown.includes("chatbot")) {
    oportunidades.push("No tiene chatbot (opportunidad para automatización)");
  }
  if (scrapedData.markdown.includes("contacto@") && !scrapedData.markdown.includes("WhatsApp")) {
    oportunidades.push("Tiene email pero no WhatsApp (opportunidad para multicanal)");
  }

  // 5. Guardar diagnóstico en Neon
  await prisma.company.update({
    where: { id: leadId },
    data: {
      analysis: {
        technologies,
        oportunidades,
        contentLength: scrapedData.markdown?.length || 0,
      },
      status: "analyzed",
      updatedAt: new Date(),
    },
  });

  return {
    technologies,
    oportunidades,
    contentLength: scrapedData.markdown?.length || 0,
  };
}

/**
 * Carga todos los agentes desde el roster
 */
async function loadAllAgents() {
  const agents = {};
  for (const [department, names] of Object.entries(roster)) {
    for (const name of names) {
      const slug = `${department}/${name}`;
      const agent = await loadAgentSlug(slug);
      if (agent) {
        agents[slug] = agent;
      }
    }
  }
  return agents;
}

/**
 * Ejecuta una tarea
 */
async function runTask(task) {
  const agent = await loadAgentSlug(task.agentSlug);
  if (!agent) {
    throw new Error(`Agente ${task.agentSlug} no encontrado`);
  }

  const execution = await prisma.agentExecution.create({
    data: {
      agentSlug: task.agentSlug,
      input: task.input,
      status: "in_progress",
    },
  });

  try {
    const result = await executeAgent(agent, task);
    await prisma.agentExecution.update({
      where: { id: execution.id },
      data: {
        output: result.data,
        status: "completed",
        tokensUsed: result.tokensUsed || 0,
        updatedAt: new Date(),
      },
    });
    return { success: true, data: result.data, executionId: execution.id };
  } catch (error) {
    await prisma.agentExecution.update({
      where: { id: execution.id },
      data: {
        error: error.message,
        status: "failed",
        updatedAt: new Date(),
      },
    });
    throw error;
  }
}
